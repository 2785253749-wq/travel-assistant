# 中国市场旅行助手 MVP：第三方实时数据 API 成本调研

调研日期：2026-07-28

## 结论先行

面向一名开发者、每天投入 5 小时以上的“标准版”公开 MVP，建议把第三方实时数据预算分成两档：

- **开发与小范围测试：0～500 元/月**。高德地图、天气、POI 在个人认证免费配额内通常为 0 元；机票、酒店、火车先用供应商测试额度、短期体验包或模拟数据。另建议准备 **500～1,500 元的一次性联调备用金**，用于购买小调用包、企业认证材料或验证数据质量。
- **公开上线、低流量验证：1,000～5,000 元/月**，并预留 **5,000～20,000 元的首期商务/保证金/许可缓冲**。这不是供应商报价，而是项目预算上限：地图费用通常只占几十到几百元，主要不确定项是可商用的机票、酒店与铁路实时价格/余票接口。
- 如果要求“真实可售库存 + 精确价格 + 直接下单/出票”，应按 **商务项目** 看待，首年建议至少预留 **3 万～10 万元**，待供应商书面报价后再调整。只做“查询并跳转平台购买”，成本与合规复杂度会显著下降。

以上区间均为**规划预留，不是供应商承诺价**。公开价格无法覆盖全部目标能力，尤其是酒店实时房价、机票可售舱位和铁路余票。

## 分项证据

### 1. 高德地图、天气与 POI

[高德开放平台基础服务计费页](https://lbs.amap.com/pages/base_service_price)给出的个人认证开发者月配额为：基础 LBS 150,000 次、地图定位 1,500,000 次、基础搜索（含关键词、周边、ID 与输入提示）5,000 次、天气 5,000 次；企业认证开发者相应为 3,000,000、30,000,000、50,000 和 5,000 次。未认证开发者的相关月配额为 0。

超出月配额后，[高德“服务升级”页](https://lbs.amap.com/upgrade)公布的基础 LBS、基础搜索和天气基准价格均为 **30 元/万次**，地图定位为 **3 元/万次**；基础 LBS 在更高调用档位可降至 24 或 18 元/万次，搜索和天气不参与该折扣。流量包有效期为 1 年。

因此，个人开发期可按 **0 元/月** 估算；即使每月超额 10 万次搜索/天气调用，按公开基准价也约为 **300 元**。这里的核心风险不是调用费，而是授权类型：[高德服务协议](https://lbs.amap.com/pages/terms/)说明，个人认证免费配额用于自然人的个人研究学习；法人或非法人组织用于商业目的须事先购买技术服务许可。公开上线前应通过工单书面确认该应用是否仍属于个人非商业用途；高德未在公开页列出技术服务许可的固定价格，因此该项为**商务询价**。

### 2. 航班与机票价格

[聚合数据“航班订票查询”官方接口页](https://www.juhe.cn/docs/api/id/818)表明接口可按出发地、目的地和日期查询，并返回 `ticketPrice` 参考票价；页面要求申请 API Key，但公开文档不展示长期单价或免费额度。因此，能否用于公开产品、价格刷新频率、可售性与长期费用均需登录后购买或商务确认。

[聚合数据“航班时刻票价查询”官方产品页](https://www.juhe.cn/docs/api/id/96)明确列出可售舱位、票价、特价票和实时起降等能力，同时其产品参数中的“计费模式”未公开具体数字，使用流程要求实名认证、购买前试用以及充值购买。故该能力应归为**商务询价/登录后报价**，不能按免费接口预算。

作为可验证的国际备选，[Amadeus Self-Service 官方定价说明](https://developers.amadeus.com/self-service/apis-docs/guides/developer-guides/pricing/)称测试环境每月有免费请求额度，生产环境仍保留月免费额度，超额按调用付费。但其中国国内航线、中文酒店覆盖与结算条件必须先做样本验证，不能直接假定可替代国内供应商。

阿里云官方 API 市场首页曾列出“航班起降时间查询”示例价 **0.1 元/次**，见[阿里云 API 市场](https://market.aliyun.com/data.aliyun.com/)。该价格只能证明“航班动态”类 API 的量级，**不等于机票实时可售价格或出票接口成本**。

建议预算：测试期 **0～300 元/月**；公开低流量查询 **500～2,000 元/月**；涉及可售舱位、下单或出票则单独商务询价，并预留保证金/预存款。

### 3. 酒店实时价格

阿里云官方 API 市场的[易源数据活动页](https://market.aliyun.com/showapiPromotion)列出“酒店查询”促销体验价 **0.01 元/100 次**。这是促销/体验 SKU，不应视为长期生产价格，也不能据此确认其返回实时可订房价。

[聚合数据关于国内酒店预定 API 的第一方说明](https://www.juhe.cn/wiki/gnjdydapijk629)描述了酒店信息、房价、房型、预订下单和订单管理能力，但没有公布统一价格。酒店库存与房价通常还涉及供应商资格、分销协议、佣金或预存款，因此生产接入应视为**商务询价**。

建议预算：仅酒店信息/静态参考价可用小流量包，测试期 **0～200 元/月**；实时可订房价公开上线按 **500～2,000 元/月** 做调用预算，另外预留商务接入资金。若采用联盟跳转而不是在应用内完成预订，可大幅降低资金和履约风险。

### 4. 火车票时刻、票价与余票

[聚合数据“火车订票查询”官方接口页](https://www.juhe.cn/docs/api/id/817)显示接口可返回 15 天内的站到站时刻、票价、可预订标志和余票数量，但公开文档不展示正式单价或长期免费额度，需申请 Key 并购买/确认套餐。

阿里云官方市场的[交通地理产品列表](https://market.aliyun.com/products/56842028/)显示，第三方服务商提供含实时班次、票价和余票的铁路查询 API；当前列表价格标签存在 **2 元/次、12 元/次** 等差异，反映不同商品/套餐口径，而不是统一铁路数据价格。另一个阿里云官方活动页曾给出火车查询 **6.3 元/10,000 次** 的促销包，见[极速数据活动页](https://market.aliyun.com/showapinewyear)。这些活动价可能过期，购买时必须以商品 SKU 和合同为准。

建议预算：测试期 **0～200 元/月**；公开低流量 **100～1,000 元/月**。如果需要真实出票、退改签或支付，不再属于简单查询，应单独评估资质、结算、实名信息处理和客服履约成本。

## 推荐采购策略

1. **第 1～2 周：零成本验证。** 完成高德个人认证并使用免费月配额；机票、酒店和火车统一做 `provider` 适配层，测试环境允许模拟数据。
2. **第 3～4 周：用 500～1,500 元做供应商对比。** 各购买最小测试包，固定 20～30 条国内热门路线与城市样本，对比实时性、失败率、字段完整度、缓存许可和商用条款。
3. **上线前：只签一个主供应商。** 先做查询与外链，不在 MVP 阶段承接支付、出票、退改和酒店履约；要求供应商书面确认公开展示、缓存时长、价格免责声明和故障 SLA。
4. **设置硬预算。** 单用户一次规划最多触发一次机票、一次酒店、一次火车查询；结果短时缓存并做日限额。按 100 个日活、每人每天各查 1 次计算，每类每月约 3,000 次。若供应商单价为 0.1 元/次，三类合计约 900 元/月；若为 1 元/次，则约 9,000 元/月。这说明预算对实际合同单价高度敏感。

## 关键不确定性与上线门槛

- “航班动态”不等于“机票实时可售价格”，“酒店信息”不等于“实时可订房价”，“列车时刻”不等于“12306 实时余票”。采购时必须按最终字段验收。
- 公开展示、缓存、二次分发和训练模型通常受数据许可限制。高德协议明确限制直接存储、缓存或抓取内部数据，需按官方文档展示或另行咨询。
- 个人实名认证能满足开发测试，但企业级商用授权、分销/出票、支付与用户实名信息处理可能要求企业主体。
- 官方公开页常仅展示试用/促销价；最低充值、保证金、发票、并发、SLA 和生产域名白名单需要登录控制台或商务询价。
- 最终预算应在取得三类交通住宿供应商的书面报价后复核；在此之前，**1,000～5,000 元/月 + 5,000～20,000 元首期缓冲**是较稳妥的 MVP 财务护栏。
