Repository-visible expected failures use the existing `app.core.errors.AppError` class with these exact code/message pairs:

| Situation | Code | Message |
| --- | --- | --- |
| requested row is absent when a mutating operation requires it | `RAG_V2_NOT_FOUND` | `RAG V2 record not found` |
| same dataset/version has a different manifest or an insert identity conflicts | `RAG_V2_VERSION_CONFLICT` | `RAG V2 corpus version conflicts with existing data` |
| PostgreSQL rejects a lifecycle or staging mutation | `RAG_V2_INVALID_LIFECYCLE` | `RAG V2 lifecycle transition is invalid` |
| activation expected-active value does not match current state | `RAG_V2_ACTIVATION_CONFLICT` | `RAG V2 corpus activation conflict` |
| Supabase/PostgREST/HTTP/row-decoding failure | `RAG_V2_UNAVAILABLE` | `RAG V2 persistence is unavailable` |

The adapter catches `postgrest.exceptions.APIError`, `httpx.HTTPError`, and invalid returned row shapes, logs only the stable operation name through `database_operation`, and raises the mapped `AppError` without exposing an upstream response body, SQL text, secret, or raw identifier. A database error code/message may select one of the stable mappings but is never returned to the caller.

Task 7 error classification is frozen separately from the general table above. For version and chunk INSERTs, structured `23505` maps to `RAG_V2_VERSION_CONFLICT`; structured `23503` (`foreign_key_violation`) and `23514` (`check_violation`) map to `RAG_V2_UNAVAILABLE`, unless an exact approved RAG V2 lifecycle/staging signal applies. Other unrecognized database, PostgREST, or HTTP failures map to `RAG_V2_UNAVAILABLE`. Lifecycle mapping requires both SQLSTATE `P0001` and a message beginning with one of these exact migration-owned prefixes:

```text
RAG V2 attraction version updates are forbidden
RAG V2 attraction version mutation requires staging
RAG V2 chunk insert is forbidden for terminal corpus
RAG V2 chunk insert requires status = 'staging'
RAG V2 chunk update is forbidden for terminal corpus
RAG V2 chunk update requires status = 'staging'
RAG V2 chunk retry reset must clear embedding errors
RAG V2 chunk embedding transition is invalid
```

Only those `P0001` plus prefix matches map to `RAG_V2_INVALID_LIFECYCLE`; arbitrary `P0001`, arbitrary English text, or every `APIError` must not be classified as lifecycle failure. The raw upstream message is never exposed through `AppError`.
