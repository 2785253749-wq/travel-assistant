## Shared Type and Signature Contract

The following names and signatures are fixed for the implementation tasks. A later task may add only types explicitly assigned to that task.

### Domain models

- DestinationLevel: string enum values province, prefecture_city, autonomous_prefecture, county_city.
- ChunkType: string enum values overview, highlights, transport, visit_advice, seasonal.
- AttractionLifecycleStatus: string enum values active, retired, merged.
- AttractionVersionStatus: string enum values included, suppressed.
- ChunkStatus: string enum values pending, embedded, failed, excluded.
- RagV2Schema: Pydantic v2 base schema with strict validation and extra fields forbidden.
- EmbeddingProfile: model, task, dimensions, input_schema_version; task is retrieval.passage or retrieval.query.
- Destination: destination_code, destination_level, destination_name, province_code, province_name, district_name, latitude, longitude.
- SourceProvenance: source_type, source_label, source_url, reviewed_on.
- StableAttraction: attraction_id, lifecycle_status, created_at, retired_at, merged_into_attraction_id.
- AttractionVersionMetadata: attraction_id, canonical_name, aliases, destination, category, tags, status.
- SemanticSection: attraction_id, chunk_type, content, source_label, source_url, source_type, reviewed_on.
- SemanticChunk: chunk_key, attraction_id, chunk_type, ordinal, normalized_content, content_hash, embedding_input_hash, source provenance fields.
- EmbeddingInput: schema_version, canonical_attraction_name, destination_name, destination_code, destination_level, chunk_type, normalized_content.
- ManifestChunk: chunk_key, chunk_type, ordinal, content_hash, embedding_input_hash, source_label, source_url, source_type, reviewed_on.
- ManifestAttraction: attraction_id, metadata_hash, chunks.
- ManifestInput: schema_version, dataset_key, embedding_profile, attractions.

### Canonicalization and hashing

- normalize_text(value: str) -> str
- normalize_content(value: str) -> str
- content_hash(value: str) -> str
- canonical_metadata_json(metadata: AttractionVersionMetadata) -> str
- metadata_hash(metadata: AttractionVersionMetadata) -> str
- build_embedding_input(*, canonical_attraction_name: str, destination_name: str, destination_code: str, destination_level: DestinationLevel, chunk_type: ChunkType, normalized_content: str) -> EmbeddingInput
- canonical_embedding_text(value: EmbeddingInput) -> str
- embedding_input_hash(value: EmbeddingInput) -> str
- canonical_manifest_json(manifest: ManifestInput) -> str
- manifest_hash(manifest: ManifestInput) -> str

### Identity and lifecycle

- AttractionIdentitySource.resolve(registry_key: str) -> UUID | None
- AttractionIdentitySource.allocate(registry_key: str) -> UUID
- rename_attraction(metadata: AttractionVersionMetadata, *, canonical_name: str) -> AttractionVersionMetadata
- merge_attraction(source: StableAttraction, target: StableAttraction | None, *, known_descendants: Collection[UUID]) -> StableAttraction
- retire_attraction(attraction: StableAttraction, *, retired_at: datetime) -> StableAttraction
- handle_corpus_absence(attraction: StableAttraction, *, known_in_source: bool) -> StableAttraction

### Semantic chunking

- CHUNK_KEY_SCHEMA_VERSION = rag-v2-chunk-key-v1
- DEFAULT_CHUNK_BUDGET = 4000
- CHUNK_TYPE_ORDER is overview, highlights, transport, visit_advice, seasonal.
- chunk_key_for(*, attraction_id: UUID, chunk_type: ChunkType, ordinal: int) -> str
- SemanticChunker(max_code_points: int = 4000)
- SemanticChunker.chunk(section: SemanticSection, *, attraction: AttractionVersionMetadata) -> tuple[SemanticChunk, ...]

### Incremental decisions

- IncrementalSubject: present_chunk, removed_chunk, attraction_absent, explicitly_retired, merged_source.
- IncrementalAction: reuse, embed, remove, exclude, no_action.
- EmbeddingIdentity: embedding_input_hash, embedding_model, embedding_task, embedding_dimensions, embedding_input_schema_version.
- PreviousEmbedding: chunk_key, identity, vector: tuple[float, ...] | None, validated_corpus: bool.
- IncrementalCandidate: subject, current_chunk_key, current_identity, previous_embeddings.
- IncrementalDecisionResult: action, reason, reused_from_chunk_key.
- decide_incremental(candidate: IncrementalCandidate) -> IncrementalDecisionResult

The exact five fields of EmbeddingIdentity are the only reuse identity fields. embedding_task must be retrieval.passage for stored passage embeddings. Vector validation must separately require non-null, finite values and valid dimensions.

## TDD Execution Protocol

For every task, the implementation worker follows this order:

1. Confirm the previous task commit and a clean working tree.
2. Add only that task's failing tests.
