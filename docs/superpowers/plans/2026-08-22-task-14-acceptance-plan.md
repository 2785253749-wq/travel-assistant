# Task 14 执行计划

## 1. 建立红灯验收测试

- 新增跨层安全旅程测试，覆盖匿名、账户 A、账户 B、管理员。
- 为公开响应和日志增加隐私白名单/拒绝字段测试。
- 为 service-role 前端泄露、迁移顺序和测试状态隔离增加契约测试。
- 先运行新增测试，确认失败来自缺失行为而非测试装配错误。

## 2. 分类并修复 12 个 wiring 基线失败

- 逐项建立失败原因、最小修复和回归命令记录。
- 只对 Task 9–13 已改变的页面/字段契约更新旧断言，并记录旧断言为何失效。
- 修复 JWT、服务组合、缓存身份、service-role 校验、状态隔离和媒体清理队列生产问题。
- 每项修复后运行最小相关测试，再运行对应后端分组。

## 3. 完成跨层回归

- 后端单元、集成、SQL 契约和用户旅程测试。
- 前端全量测试、管理员页面测试和所有静态 JavaScript `node --check`。
- `git diff --check`，并检查 service-role 密钥未出现在前端资源和公开响应。

## 4. 编写部署、回滚和交接文档

- 记录迁移探测和执行顺序 `010 → 011 → 012`。
- 记录应用/静态资源部署顺序、冒烟检查、兼容回滚和故障处置。
- 记录测试结果、已知问题、变更文件白名单和未提交状态。

## 5. 安全整理范围

- 只读检查 `git status --short`、`git diff --name-only` 和未跟踪 Task 14 文件。
- 不删除、不恢复、不批量格式化其他脏文件。
- 不提交；最终报告实际变更范围及仍存在的非 Task 14 文件。

## 验证命令清单

```text
pytest -q
node --test tests/frontend/*.test.js
node --check app/static/*.js
git diff --check
```

若某条命令在 Windows shell 中不支持通配符展开，则使用仓库已有测试脚本或逐文件枚举执行，保持验证范围等价。
