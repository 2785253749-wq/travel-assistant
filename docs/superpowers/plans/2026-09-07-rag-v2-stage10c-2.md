# RAG V2 Stage 10C-2 Runtime Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire the validated RAG V2 retrieval path into the real `travel_knowledge` runtime path with deterministic grounded answers and legacy RAG fallback, without changing Train, Hotel, Weather, or normal Planner behavior.

**Architecture:** Use the existing `travel_knowledge` routing seam. Construct RAG V2 runtime dependencies in the composition root, invoke a thin V2 knowledge adapter first, map retrieved evidence deterministically to the existing reply/citation contract, and fall back to the current legacy knowledge service when V2 is empty or unavailable.

**Tech Stack:** Python, FastAPI application runtime, Supabase/PostgreSQL pgvector through the existing RAG V2 repository, Jina `retrieval.query` embeddings through the existing query embedder, pytest.

**Spec:** `docs/superpowers/specs/2026-09-07-rag-v2-stage10c-2-design.md`

## Target Module Contract

Create app/rag_v2/knowledge.py as a module-local runtime adapter. Do not export it through app/rag_v2/__init__.py.

Use these exact concepts:

    V2KnowledgeStatus = Literal["grounded", "empty", "unavailable"]

    @dataclass(frozen=True)
    class V2KnowledgeResult:
        status: V2KnowledgeStatus
        reply: str | None
        evidence: tuple[RetrievalEvidence, ...]
        error_code: str | None = None

    class V2KnowledgeAnswerer(Protocol):
        def answer(
            self,
            query: str,
            *,
            destination_code: str | None = None,
            destination_level: DestinationLevel | None = None,
            province_code: str | None = None,
            attraction_id: UUID | None = None,
        ) -> V2KnowledgeResult: ...

    class RagV2KnowledgeAdapter:
        def __init__(self, *, retrieval: RetrievalService) -> None: ...
        def answer(
            self,
            query: str,
            *,
            destination_code: str | None = None,
            destination_level: DestinationLevel | None = None,
            province_code: str | None = None,
            attraction_id: UUID | None = None,
        ) -> V2KnowledgeResult: ...

The adapter calls RetrievalService.retrieve exactly once per answer with query, dataset_key="rag-v2-production", and the four supplied filters. It passes no candidate_k, final_k, or score_threshold keyword, preserving the validated RetrievalService defaults: candidate_k=40, final_k=6, and score_threshold=0.60.

For valid non-empty evidence, reply is the ordered evidence contents joined by two newlines. The evidence tuple is returned unchanged. Each evidence item must have non-empty content, an HTTPS source_url, and source_type in official, government, trusted_provider. A malformed item returns status unavailable and error_code RAG_V2_MALFORMED_RESULT.

JinaQueryEmbedder already normalizes provider failures to AppError code RAG_V2_EMBEDDING_UNAVAILABLE. RagV2Repository.match_chunks already normalizes PostgREST, HTTP, response-shape, and candidate-validation failures to AppError code RAG_V2_UNAVAILABLE. These are the only AppError codes treated as expected V2 operational-unavailable conditions by the adapter. A successful RPC returning no active candidates produces an empty RetrievalResult and therefore status empty; no separate no-active AppError is invented. RAG_V2_NOT_FOUND, RAG_V2_VERSION_CONFLICT, RAG_V2_ACTIVATION_CONFLICT, RAG_V2_INVALID_LIFECYCLE, ValueError, TypeError, and other unclassified exceptions propagate to the existing application error boundary. Raw provider/database exception text never crosses the runtime response boundary.

Add UnavailableRagV2KnowledgeAdapter with the same answer signature. When required runtime V2 configuration is absent, its answer method returns exactly V2KnowledgeResult(status="unavailable", reply=None, evidence=(), error_code="RAG_V2_UNAVAILABLE"). It does not expose missing secret names, secret values, or raw configuration details in the user response.

## Design Traceability Checklist

1. Purpose: connect validated retrieval to runtime travel_knowledge.
2. Baseline: preserve the direct knowledge branch and Planner separation.
3. Decision: router-triggered integration; no global retrieval or Planner tool.
4. Flow: classify, invoke V2, return grounded evidence or legacy fallback.
5. Responsibilities: composition constructs; adapter formats; RetrievalService retrieves; legacy service falls back; agent routes.
6. Adapter: query/trusted filters, deterministic result, empty/unavailable signals, no raw errors.
7. Destination: no resolver, no guessed code, omit unknown filters.
8. Grounding: evidence-only, no LLM, preserve URLs/labels, private IDs.
9. Errors: fallback without retry/rollback.
10. Isolation: Train, Hotel, Weather, Planner, legacy RAG, non-knowledge unchanged.
11. Provenance: map through SourceCitation validation.
12. Construction: Settings to repository to Jina provider to query embedder to RetrievalService to adapter to agent.
13. Files: adapter plus composition/agent/test seams only.
14. Tests: adapter, provenance, fallback, routing, isolation, public response, existing suite.
15. Acceptance: production dataset, active-only, threshold 0.60, evidence-only, URLs, fallback, no guessed code.
16. Non-goals: no migration/data/activation/import/Planner tool/classifier/resolver/retry/circuit breaker/rollback/cache.
17. Rollout: local tests, regressions, controlled API smoke, no corpus mutation.
18. Handoff: implementation starts only after plan approval.
