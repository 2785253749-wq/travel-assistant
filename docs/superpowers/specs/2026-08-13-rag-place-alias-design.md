# RAG 试点景点别名识别设计

## 目标

让用户在未写城市时，仍可就知识库中唯一归属试点地区的景点提问；不确定时保持拒答，不编造地区。

## 范围与规则

1. 服务端维护一份小型本地别名表，键为规范化景点名称，值为唯一的试点地区。
2. 仅当用户问题未提供地区、且恰好命中一个别名时，系统在内部为 RAG 检索补充该地区上下文。
3. 用户原始问题不改写；补充的地区只作为检索上下文，不显示为用户输入。
4. 没有命中、命中多个地区、或地区不在试点范围时，固定中文拒答并提示用户补充目的地城市。
5. 直接天气、行程收集、修改行程等既有意图优先级不变；别名规则只服务于独立知识问答。

## 数据与接口

- 别名表随服务端代码发布，不请求第三方接口。
- 解析器返回 `str | None` 的地区；`None` 表示未知或歧义。
- RAG 服务仍使用既有试点地区白名单，不允许全库兜底检索。

## 验收与测试

- “鼓浪屿游玩前需要怎样安排？”可进入厦门知识检索并带有效中文来源。
- 模拟歧义或未知地点保持拒答，提示补充城市，且不调用检索模型。
- 真实评测执行原始用户问题，不再通过测试代码为问题前置城市名。
- 原有明确城市知识问答、天气问答与行程收集回归通过。
