# Task 14 跨层安全、响应式和部署验收规格

## 目标

在不扩大现有脏文件范围、不提交代码的前提下，验证并收紧社区公开能力、互动能力和管理员审核能力的跨层边界，修复 12 个既有 wiring 基线失败，并产出可执行的部署、回滚和交接材料。

## 不可变约束

- 只有明确由 Task 9–13 改变的契约，才允许更新原有测试断言；每个更新必须在测试注释或交接文档中记录旧断言失效的原因。
- JWT、缓存身份、service-role 配置和媒体清理队列相关失败不得通过放宽断言、跳过测试或扩大 mock 来隐藏。
- service-role 密钥只存在于后端配置和后端运行路径，不进入静态资源、浏览器运行时配置、HTML 或公开 API 响应。
- 测试必须隔离缓存、依赖覆盖和内存仓储状态；测试结束后恢复覆盖并清空共享状态。
- 迁移只执行目标环境尚未应用的 `010 → 011 → 012`，不重复执行，也不通过回滚删除表。
- 日志只记录哈希主体和稳定错误码，不记录邮箱、原始 UUID、Storage 路径、私有行程正文或令牌。
- 不提交、不删除、不整批整理其他脏文件。

## 契约更新判定

允许更新的旧断言仅限：

1. 社区入口由复用首页壳改为 Task 11 的独立社区页面。
2. 管理员入口由普通首页壳改为 Task 13 的管理员页面。
3. Task 9–13 新增的公开字段白名单、签名图片 URL、互动审核状态和管理员路由。
4. Task 12 明确要求的 `avatar_path` 等生产接口必填字段。

以下失败必须修复生产 wiring 或状态隔离，不得更新为更宽松断言：

- JWT 解析与开发/生产服务组合；
- profile/community 模块缓存身份与依赖覆盖；
- service-role 配置校验；
- 媒体清理队列的成功、重试和耗尽状态；
- 跨测试的内存仓储、缓存和依赖覆盖泄漏。

## 验收矩阵

### 匿名用户

- 可读取已公开游记、公开创作者资料和已审核评论。
- 不可读取草稿、私有行程、待审评论、收藏状态、审核队列或管理接口。
- 公开图片只能是短期签名 URL；响应和日志不得暴露 Storage 路径或内部身份字段。

### 账户 A 与账户 B

- A 的草稿、私有行程、媒体、收藏、待审评论和删除权限不被 B 读取或操作。
- B 只能看到 A 已发布且仍公开的快照及已审核互动。
- A/B 的缓存身份、依赖覆盖和内存仓储在测试中相互隔离。

### 管理员

- 管理员可读取游记、评论、举报审核队列及游标分页数据。
- 队列图片只返回短期签名 URL，不返回 Storage 路径。
- 通过、驳回、驳回原因和举报关闭必须走明确审核操作；`actioned` 不隐式隐藏目标内容。
- 非管理员得到 403，且前端清空队列后跳转首页。

## 隐私白名单验收

为公开、互动和管理员响应建立字段白名单测试；测试明确拒绝：邮箱、完整 UUID、Storage 路径、私有行程字段、访问令牌和未签名媒体引用。日志测试使用捕获 logger，允许稳定错误码与哈希主体，拒绝上述敏感值。

## 部署与回滚验收

- 部署前确认目标环境迁移记录，仅补执行未应用的迁移 `010`、`011`、`012`。
- 迁移完成后部署后端，再部署静态资源，执行匿名/双账户/管理员冒烟旅程。
- 回滚应用代码时保留已应用的新增表、索引和 RPC；不执行删除表的逆向迁移。
- 若发现数据或权限异常，暂停写入并使用明确的管理员操作或前向修复迁移处理，不用破坏性回滚。
- 交接文档列出测试命令、结果、已知基线、变更文件范围和未提交状态。
