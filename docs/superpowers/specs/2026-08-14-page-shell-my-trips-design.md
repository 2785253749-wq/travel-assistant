# 页面框架与我的行程设计

## 背景

当前 Voyage 前端是单页静态结构。探索地图、目的地推荐、天气卡、AI 助手、行程生成和账户弹窗已经存在，但顶部“我的行程”和“社区”仍是导航占位按钮。现阶段先完成核心页面框架和“我的行程”闭环，社区只提供明确的占位状态。

## 目标

把现有单页升级为可切换的三视图结构：探索、我的行程、社区；复用现有登录、行程列表、分享和重命名能力，不引入复杂前端路由或新框架。

## 非目标

- 本阶段不实现社区帖子、评论、点赞、审核或搜索。
- 不重写现有地图、AI 助手、天气和行程生成逻辑。
- 不改变后端认证、行程和分享接口。

## 页面状态

使用一个有限页面状态：

```text
activeView = explore | trips | community
```

- `explore`：显示现有地图、目的地推荐和天气卡。
- `trips`：登录后显示私有行程列表；未登录时显示登录提示和账户入口。
- `community`：显示“社区功能即将开放”的空状态，不伪造帖子内容。

切换视图时更新导航按钮的 `aria-current`，只显示当前视图，不刷新页面；当前 AI 助手、已生成行程和账户会话保持不变。

## 结构与数据流

### HTML

- 保留现有 `#explore-page`。
- 将当前行程历史区域整理为 `#trips-page`，包含标题、登录提示、列表和空状态。
- 新增 `#community-page`，包含标题、说明和占位卡片。
- 导航按钮增加 `data-view="explore|trips|community"`。
- 继续复用分享和重命名对话框。

### JavaScript

- 新增 `switchView(view)`，负责视图显隐、导航状态和焦点移动。
- 复用 `refreshHistory()` 请求 `/api/trips`，不复制行程数据访问逻辑。
- `trips` 视图在登录状态变化后刷新；退出登录后清空列表并显示登录提示。
- `community` 视图只渲染固定空状态，不请求未存在的社区接口。
- 原有探索选择、天气请求、AI 对话和行程渲染继续使用现有状态对象。

### CSS

- 为三种页面状态复用统一的页面标题、卡片、空状态和错误状态样式。
- 行程列表在桌面端使用卡片网格，在窄屏下改为单列。
- 保持现有 Voyage 蓝色主色、圆角、阴影和可见焦点样式。

## 错误与空状态

- 未登录进入“我的行程”：提示“登录后查看已保存的行程”，提供打开账户菜单的操作。
- 已登录但无行程：显示“还没有保存的行程”，不显示错误。
- `/api/trips` 请求失败：显示可重试提示，不影响探索页和 AI 助手。
- 社区页：明确说明功能尚未开放，不提供不可用的交互按钮。

## 验收标准

1. 点击三个导航按钮只切换视图，不刷新页面。
2. 探索页原有地图、天气卡和目的地选择行为不回归。
3. 未登录进入“我的行程”时，登录提示可见且账户入口可用。
4. 登录后能加载并展示 `/api/trips` 返回的行程列表。
5. 现有行程的保存、分享、撤销分享和重命名入口继续可用。
6. 社区页显示真实的空状态，不调用不存在的接口。
7. 键盘用户能感知当前导航项和视图标题，焦点不会落入隐藏内容。

## 测试范围

- `tests/frontend/app.test.js`：导航切换、未登录行程页、已登录行程列表、社区空状态。
- 现有地图测试和前端全量测试必须继续通过。
- 手动浏览器验收：桌面宽度、窄屏宽度、登录/退出登录、空列表和请求失败状态。
