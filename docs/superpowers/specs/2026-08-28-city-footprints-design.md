# 城市足迹云端同步与区域点亮设计

## 背景

当前“我的足迹”已经具备独立导航、账户可见性、探索页添加入口和高德地图适配器，但足迹仍保存在浏览器 Local Storage 中，地图只显示地点 Marker。用户换浏览器、换设备或清理站点数据后无法恢复足迹，也不能按照城市行政边界形成直观的区域点亮效果。

本设计将足迹升级为当前登录账户的云端私有数据，并使用高德行政区域查询返回的城市边界在现有地图上绘制 Polygon。高德只提供公共地理边界；Supabase 是用户足迹的唯一事实来源。

## 目标

- 足迹按地级市或同级行政区记录，以城市 `adcode` 作为稳定标识。
- 登录账户可以跨浏览器、跨设备读取自己的足迹。
- 已添加城市在高德地图上以完整行政边界点亮。
- 支持添加城市、修改到访日期、定位到城市和移除城市。
- 探索页中的城市或景点都可以加入足迹；景点归并到所属城市。
- 同一账户的同一城市最多存在一条足迹。
- 未登录用户不能读取或修改私人足迹。
- 高德服务异常时，足迹列表仍然可用，地图降级为中心点 Marker 或静态视图。
- 现有 Local Storage 足迹可以安全、幂等地迁移到云端。

## 非目标

- 不记录 GPS 连续轨迹、实时位置或精确行动路线。
- 不在第一阶段保存独立景点足迹；景点只作为添加城市足迹的入口。
- 不一次性下载或打包全国城市 GeoJSON。
- 不提供公开分享、好友排行、足迹动态或社区发布。
- 不根据私人行程自动推断用户确实到访过某城市。
- 不把高德 Web 服务密钥、Supabase service-role key 或完整用户 UUID发送给公开页面。

## 方案选择

采用“Supabase 私有足迹 + 服务端高德边界适配器 + 前端 Polygon 渲染”。

浏览器直连高德行政区域 Web 服务会暴露服务端 Key，并让配额、缓存和错误处理散落在客户端，因此不采用。将全国边界作为静态 GeoJSON 随应用发布会增加资源体积和更新成本，也不符合按需加载原则，因此不采用。

高德行政区域查询仅用于按 `adcode` 获取城市名称、中心点和边界折线。边界由服务端按需查询、规范化和缓存。官方接口约束以[高德行政区域查询文档](https://lbs.amap.com/api/webservice/guide/api/district)为准。

## 领域模型

### UserFootprint

一条 `UserFootprint` 表示某个账户确认到访过一个城市：

```text
id: UUID
user_id: UUID
city_adcode: string
city_name: string
province_adcode: string
province_name: string
center_lng: number
center_lat: number
visited_at: date
created_at: datetime
updated_at: datetime
```

约束：

- `(user_id, city_adcode)` 唯一。
- `city_adcode` 必须是已由服务端城市目录验证的六位行政区代码。
- `visited_at` 不能晚于提交当天。
- `city_name`、省份字段和中心点由服务端城市目录提供，不信任客户端传值。
- 列表按 `visited_at desc, created_at desc` 排序。

### DistrictBoundary

`DistrictBoundary` 是公共地图缓存，不包含用户身份：

```text
city_adcode: string
city_name: string
province_adcode: string
province_name: string
center: [longitude, latitude]
rings: Array<Array<[longitude, latitude]>>
source_updated_at: datetime | null
cached_at: datetime
```

高德返回的多段 polyline 必须转换为多个闭合 ring。服务端拒绝空边界、非有限坐标、超出中国有效经纬度范围的数据以及超过响应大小上限的数据。

## 数据库与权限

新增 `public.user_footprints` 表。外键 `user_id` 指向 `auth.users(id)`，用户删除时级联清理足迹。

RLS 策略只允许 `auth.uid() = user_id` 的账户执行 `select`、`insert`、`update` 和 `delete`。客户端不能通过请求体指定其他 `user_id`，应用服务必须从已验证的访问令牌取得用户身份。

城市边界属于公共数据，可以使用独立的 `district_boundary_cache` 表或等价服务端缓存。它不开放用户写入，不与私人足迹联表公开查询。

## 后端组件

### FootprintRepository

负责当前账户足迹的持久化：

- `list_owned(user_id)`：返回该账户全部足迹。
- `upsert_owned(user_id, city, visited_at)`：按账户和 `adcode` 幂等创建或更新。
- `update_visited_at(user_id, footprint_id, visited_at)`：只修改当前账户记录。
- `delete_owned(user_id, footprint_id)`：只删除当前账户记录。

仓库接口不处理高德请求，便于使用内存实现进行应用测试。

### CityDirectory

负责把城市 `adcode` 或当前试点城市 ID 解析为规范城市数据。第一阶段支持当前探索页已有城市，并允许通过高德行政区查询扩展到其他城市。所有写入都必须先经过该组件验证。

### DistrictBoundaryProvider

负责调用高德行政区域查询、解析 polyline、限制响应大小和返回结构化边界。高德 Key 只从服务端配置读取。上游超时、配额耗尽、非成功状态和格式错误统一映射为可识别的 unavailable 结果，不泄露原始密钥或内部响应。

### DistrictBoundaryService

负责缓存和降级：

1. 查询本地缓存。
2. 命中且未过期时直接返回。
3. 未命中时调用 Provider 并写入缓存。
4. 上游失败但存在过期缓存时返回旧缓存并标注 stale。
5. 无任何边界时返回城市中心点和 unavailable 状态。

同一 `adcode` 的并发缓存未命中必须合并为一次上游请求。建议成功缓存 30 天，失败结果短暂缓存 5 分钟，避免持续冲击配额。

## API

所有足迹写接口和列表接口都要求 Bearer Token，并沿用现有私有 API 的一次刷新重试规则。

### `GET /api/footprints`

返回当前账户足迹列表。响应不包含完整用户 UUID、邮箱或任何其他账户资料。

### `POST /api/footprints`

请求体：

```json
{
  "city_adcode": "350200",
  "visited_at": "2026-08-28"
}
```

服务端验证城市并执行幂等 upsert。重复提交返回同一城市记录，不产生第二条数据。

### `PATCH /api/footprints/{footprint_id}`

只接受 `visited_at`，并验证记录归当前账户所有。

### `DELETE /api/footprints/{footprint_id}`

删除当前账户记录。不存在或不属于当前账户的 ID 对外统一按不存在处理。

### `GET /api/map/districts/{city_adcode}`

返回规范化城市边界、中心点和 `fresh`、`stale` 或 `unavailable` 状态。该接口不返回高德 Key、上游 URL或原始错误正文。

## 前端状态与数据流

足迹页进入时：

1. 未登录则只显示登录提示，不请求私人 API。
2. 已登录则加载 `/api/footprints`。
3. 立即渲染统计和列表。
4. 针对当前足迹中的唯一 `city_adcode` 并发受限地加载边界。
5. 地图逐个绘制城市 Polygon；边界不可用时绘制中心点 Marker。
6. 离开足迹页时销毁 Polygon、Marker、地图事件和未完成请求。

页面必须维护加载代次或 AbortController。账户切换、退出登录或快速切换页面后，旧请求不得恢复上一账户的数据。

## 地图交互

- 已点亮城市使用青绿色半透明填充和清晰边框。
- 鼠标悬停或键盘聚焦时提高填充透明度并显示城市名称。
- 点击 Polygon 后，在右侧列表定位并突出对应城市。
- “定位到地图”调用地图适配器聚焦该城市边界。
- 有多个足迹时，首次加载自动适配所有边界范围。
- 没有足迹时保持全国默认视图。
- 删除足迹后立即移除对应 Polygon；失败则恢复列表和地图状态并提示重试。
- 地图不可用时保留可操作的城市列表，不阻断修改和删除。

地图适配器必须以 `mount/update/focus/destroy` 为公开生命周期，避免页面往返后重复创建实例或绑定事件。

## 页面布局

保留当前左侧地图、右侧列表结构，完善以下内容：

- 顶部统计显示“城市数”“省份数”“最近到访”。
- 右侧增加城市搜索和添加入口。
- 列表项显示城市、省份、到访日期，并提供“定位”“修改日期”“移除”。
- 添加城市时要求选择到访日期，默认当天。
- 探索页城市与景点卡片使用“点亮这座城市”文案；景点根据所属城市 `adcode` 归并。
- 已添加城市显示“已点亮”，再次点击不直接删除，避免误操作；删除仅在足迹页执行。

## Local Storage 迁移

现有数据键为 `voyage:footprints:<user_id>`。迁移只在用户登录且云端列表首次成功加载后执行：

1. 读取当前稳定用户 ID 对应的旧数组。
2. 将城市条目直接映射到 `adcode`；景点条目通过当前探索数据映射到所属城市。
3. 忽略无法安全识别城市的条目，并保留本地原始数据。
4. 对唯一城市执行批量或逐条幂等 upsert。
5. 全部可迁移条目成功后写入版本化迁移标记。
6. 一个版本周期内不删除旧键，页面也不再以旧键作为事实来源。

迁移失败不能覆盖已经从云端加载的数据，下次登录可以重试。账户 A 的迁移标记不能影响账户 B。

## 错误处理

- Supabase 暂时不可用：显示可重试错误，不回退为 Local Storage 写入。
- 401：按现有认证边界刷新一次；仍失败则清理过期会话并显示登录入口。
- 403：显示无权访问，不展示旧账户残留数据。
- 高德边界不可用：列表继续工作，地图使用中心点 Marker 或静态降级。
- 添加重复城市：返回现有记录并更新页面为已点亮。
- 乐观删除失败：恢复被移除的列表项和 Polygon。
- 城市搜索无结果：显示明确空状态，不允许保存自由文本城市。

## 性能与配额

- 仅为用户实际保存的城市加载边界，不预加载全国城市。
- 边界请求并发数限制为 3。
- 服务端按 `adcode` 缓存并合并并发请求。
- 前端同一挂载周期内复用边界 Promise。
- Polygon 更新复用已有地图实例；不因列表小改动重新加载高德脚本。
- 对异常大的边界响应设置点数和字节上限。

## 安全与隐私

- 足迹是私人账户数据，不出现在公开分享、社区或搜索结果中。
- 前端不展示邮箱、完整 UUID、Storage 路径或服务端密钥。
- 服务端从认证上下文决定 `user_id`，不接受客户端传入所有者。
- RLS 是最终数据隔离边界，前端隐藏内容不能代替后端授权。
- 日志只记录 request ID、错误码和 `adcode`，不记录访问令牌或完整私人足迹列表。

## 测试与验收

### 后端

- 两个账户的列表、更新和删除严格隔离。
- `(user_id, city_adcode)` 幂等去重。
- 未来到访日期、非法 `adcode` 和自由文本城市被拒绝。
- 高德 Key 只在服务端请求中使用。
- 边界成功缓存、并发合并、过期缓存降级和短期失败缓存正确。
- 无边界时仍返回中心点降级信息。

### 前端

- 未登录不请求私人足迹。
- 登录后能加载、添加、修改日期和删除。
- 账户切换不会显示上一账户足迹。
- 已保存城市创建 Polygon，删除后 Polygon 消失。
- 边界失败时创建 Marker，列表仍可操作。
- 页面前后切换不重复创建地图、监听器或请求。
- 地图定位、统计和当前列表同步。
- Local Storage 数据只迁移一次，景点归并为城市且重复城市去重。

### 浏览器验收

- 无足迹账户显示全国视图和明确空状态。
- 添加厦门后点亮厦门行政边界，刷新后仍存在。
- 换浏览器登录同一账户后仍能恢复厦门足迹。
- 同一省份添加多个城市时，城市数和省份数正确。
- 修改到访日期后排序和“最近到访”同步更新。
- 高德请求失败时仍可查看和删除云端足迹。
- 退出登录后私人列表和地图图层立即清空。

## 交付边界

实现按四个可独立审查的阶段交付：

1. 数据表、RLS、领域模型、仓库和足迹 API。
2. 高德行政区 Provider、缓存服务和边界 API。
3. Polygon 地图适配器、足迹页交互和探索页入口。
4. Local Storage 迁移、完整降级、全量测试和浏览器验收。

每个阶段先增加失败测试，再写最小实现，并只暂存该阶段相关文件。
