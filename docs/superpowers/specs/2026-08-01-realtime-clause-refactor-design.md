# 实时查询分句判定重构设计

## 目标

修复中文冒号和换行将单个“时间 + 旅行对象 + 实时价格需求”请求拆散后漏拒的问题，同时保留用户明确不查询动态价格时的正常行程规划。

## 决策

1. 先按中文/ASCII 逗号、分号、句末标点、冒号和换行分割为短子句。
2. 每个子句独立识别“明确不查询价格/库存”的 opt-out；该 opt-out 只豁免自身子句。
3. 对每个连续的相邻子句窗口聚合时间标记、旅行对象和动态需求三类信号；任一窗口同时具备三类信号且不存在同窗口内对该动态查询的明确否定时，拒答。
4. 不跨句扩展安全措施的正则范围；安全保证判断保持现有局部 span 规则。

## 验收

- `明天机票：价格多少` 和换行等价写法拒答为 `UNVERIFIABLE_REALTIME_REQUEST`。
- `机票价格不用查：明天只帮我安排行程` 不拒答。
- `机票价格不用查：明天酒店价格多少` 拒答。
- R001/R006/R014 及已有正常安全建议、实际安全措施回归仍通过。
- 不修改评估案例、期望值、门槛、基线或 Task 11 文件。
