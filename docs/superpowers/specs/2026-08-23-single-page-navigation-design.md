# 单页导航与认证边界设计规格

## 背景

当前探索、行程、社区、个人信息和管理员页面既有独立页面，又存在不同的导航与认证行为。管理员页面在过期会话或非管理员账户下可能在登录页、管理员页和首页之间循环跳转。用户确认采用 B 方案：五个主要视图在同一应用壳内切换，不因内部导航刷新页面。

## 目标

- 在主应用壳内提供探索、我的行程、社区、个人信息、管理员入口五个内部视图。
- 使用 History API 切换内部视图，支持浏览器前进、后退和直接打开深链接。
- 保留现有 API、数据库权限和公开数据白名单，不把管理员权限判断下放到前端。
- 让管理员认证失败可恢复：401 清理过期会话后展示登录入口；403 展示无权限状态，不自动重定向形成循环。
- 在迁移期间保留独立 URL 的直接加载能力，避免破坏现有分享链接和部署入口。

## 非目标

- 不重做社区数据模型、互动 API 或管理员审核 API。
- 不修改 Supabase RLS、管理员角色表或生产凭据。
- 不把邮箱、完整 UUID、Storage 路径或私有行程加入公开响应。
- 不批量整理现有无关脏文件。

## 路由与导航

| URL | 视图 | 访问边界 |
| --- | --- | --- |
| `/` | 探索 | 公开；登录后可使用私有能力 |
| `/#trips-page` | 我的行程 | 未登录显示登录提示；登录后显示私有行程 |
| `/community` | 社区 | 公开浏览；发布和互动要求登录 |
| `/profile` | 个人信息 | 未登录显示登录提示；登录后显示当前账户资料 |
| `/admin/community` | 管理员 | 需要登录且具备 admin 角色 |

主应用内部导航通过 `history.pushState` 或 `history.replaceState` 更新地址并挂载视图；内部导航不使用 `location.href`。`popstate` 必须重新选择视图。直接打开社区、个人信息或管理员 URL 时，服务端页面入口或兼容包装仍可正常加载。

## 认证状态机

1. 应用初始化读取运行时配置并恢复会话。
2. 管理员视图收到 401：清空本地/客户端会话，显示登录视图或登录入口，保留 `return_to=/admin/community`。
3. 管理员视图收到 403：清空队列内容，渲染“当前账户没有社区管理员权限”和返回探索操作；不跳首页、不跳登录页。
4. 登录成功后只在目标确实是内部路由时回到目标；无效或外部 `return_to` 回到探索。
5. 会话失效事件清理乐观状态和管理员队列，视图内显示可恢复的登录状态，不重复触发重定向。

## 视图生命周期

每个视图提供可重复调用的 `mount(root, context)` 和必要的 `unmount()` 或清理函数。路由切换前移除事件监听、请求回调和定时器，避免同一页面重复挂载导致重复请求。现有独立页面脚本可以作为兼容入口调用同一控制器，不复制业务规则。

## 安全与可访问性

- DOM 文本使用 `textContent` 或安全 DOM API；图片只接受短期签名 URL。
- 管理员队列只有在 API 返回成功后渲染，403 时不残留上一账户内容。
- 导航项使用链接或按钮的语义元素，当前视图设置 `aria-current`，交互按钮保持可见焦点。
- 管理员审核继续使用服务端角色校验，前端隐藏入口不视为权限控制。

## 验收标准

- 五个导航项在同一应用壳中切换，不发生整页刷新。
- 浏览器前进、后退和刷新后视图与 URL 一致。
- 过期管理员会话不会在 `/auth` 与 `/admin/community` 间循环。
- 普通账户访问管理员视图只显示无权限状态，不显示队列，也不重定向循环。
- 现有社区、行程、资料和管理员 API 测试保持通过；新增路由、认证边界和视图清理测试通过。
