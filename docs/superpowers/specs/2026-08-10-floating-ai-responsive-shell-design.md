# 悬浮 AI 助手与响应式页面壳设计

## 目标

Voyage 风格前端不再使用占据页面一侧的长对话栏。AI 助手改为右下角悬浮入口，并在桌面和移动网页中保持可访问、可关闭和不遮挡主要旅行内容。

## 布局

- 桌面端（宽度大于 900px）：探索、我的行程、社区使用主内容区；右下角显示圆形“AI”按钮。打开后显示宽 380px、高最多 520px 的浮层对话窗，不改变主内容宽度。
- 移动端（宽度不大于 900px）：同一个按钮打开底部抽屉，宽度接近视口，高度最多 78vh；主内容保持单列可滚动。
- 地图、城市和景点选择产生的本地推荐消息写入该浮层。用户发送的规划资料继续使用现有 `collect -> confirm` API 流程。

## 交互与状态

- 按钮包含可见文字或无障碍名称“打开旅行助手”。
- 对话窗包含关闭按钮；按 Escape 关闭；关闭后焦点返回悬浮按钮。
- 页面不会在初次加载时自动打开助手。地图选择可写入推荐消息，但不发起模型调用。
- 窄屏和 `prefers-reduced-motion: reduce` 下移除弹出/缩放动画，避免眩晕并降低布局抖动。

## 安全边界

- 不将 API 密钥或原始 itinerary 写入浏览器。
- 不绕过既有确认、额度、拒答、身份认证或服务端保存逻辑。
- 本地地图推荐不调用 `/api/chat`；只有用户主动发送文本时才使用既有聊天 API。

## 验收

- 桌面端助手初始关闭，点击后出现浮层且不会隐藏主内容。
- Escape 和关闭按钮均可关闭，并恢复焦点。
- 小屏样式改为底部抽屉；动画降级样式存在。
- 既有前端测试、Python 测试和离线评测维持通过。
